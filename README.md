# Cisco Fiber Ring Monitoring Dashboard

A web-based, read-only monitoring dashboard for Cisco switches connected through a fiber ring — a single self-contained HTML file (inline CSS + JS, no build step, no backend, no external/CDN dependencies).

## Live demo

Once GitHub Pages is enabled (see below), the dashboard is served at:

```
https://<your-username>.github.io/<repo-name>/
```

## What's inside

A dark NOC-style dashboard simulating the platform described in the specification:

- **Overview** — device/link/ring-health KPIs, mini-topology, 24h health trend, recent incidents
- **Interactive Topology** — SVG ring graph, color-coded links, click a link for a full detail panel (RX/TX, optical DOM, errors, incident). Buttons to simulate a fiber cut and restore.
- **Fiber Monitoring / Traffic Analytics / SFP DOM** — per-link tables, time-series charts, optical gauges with thresholds
- **Path Analysis** — VLAN-aware shortest-path traced on the topology with hop-by-hop evidence
- **Switch Inventory / Auto Discovery** — searchable inventory; CIDR scan with authorized-scope enforcement (in-scope ranges run, out-of-scope ranges are rejected)
- **Alerts & Events / Reports / Settings** — alert acknowledge/close, generated reports, SNMP profiles, polling schedules, thresholds, scopes, notifications, RBAC

Telemetry is generated by a client-side simulation engine (counter deltas, optical drift, alert generation) so every screen shows live moving data. To make it poll real switches, wire the same UI to the FastAPI + PySNMP + PostgreSQL backend from the spec; the simulated data layer is isolated in the `APP.SIM` module and page renderers use a single `refreshActive()` hook.

## Files

- `index.html` — the entire application (open directly in any browser, or serve via GitHub Pages)
- `.nojekyll` — tells GitHub Pages to serve the file as-is without Jekyll processing

## Publish to GitHub Pages

1. Create a new public repository on github.com (e.g. `cisco-fiber-ring-monitor`).
2. Upload `index.html` and `.nojekyll` to the repo root (web UI: "Add file → Upload files", or push via git).
3. Repository **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)` → Save**.
4. Wait ~30–60 seconds, then open the URL shown at the top of the Pages settings.

No server, no build, no environment variables required.
